## 실습별 기록

### 1주차 — AX 아이디어 보드 (`src/`)
업무별 AI 활용 아이디어를 카드로 모으는 웹앱. 카드 추가(빈칸이면 막음), 태그 필터, 삭제 전 확인창, 개수 표시, 새로고침 후 유지(localStorage `ax-board-ideas`).
- 배운 점: CLAUDE.md에 규칙을 적어 두고 AI와 기능을 하나씩 늘리는 방식. 공용 서버에서는 `--host`, 배정 포트, Ctrl+Z로 멈춘 프로세스가 포트를 잡는 문제 등 환경 함정이 많다.
- 원래 작업 폴더에는 수정 · 상태 · 검색 · JSON 내보내기까지 붙인 확장판이 있지만, 이 저장소에는 수업용 기본판만 올렸다.

### 수업 서버 환경 — 실습 1~3 (PR #15)
VS Code로 수업 SSH 서버에 접속하고 Claude Code · Codex를 연결했다. 서버 접속 · 확장 설치 · 로그인은 직접 한다는 원칙(D1).

### 3주차 — GitHub로 일하는 법 (PR #1 · #3 · #4 · #6 · #7)
- #1 제목 변경: 브랜치 → PR → Comment 리뷰 → merge 한 바퀴.
- #3 삭제 확인창(Issue #2), #6 아이디어 개수(Issue #5): Issue로 일을 정하고 `Closes #번호`로 자동 종료.
- #4 README: 새 폴더에 clone해서 README대로만 실행해 보는 재현 검증.
- #7 CLAUDE.md Git 규칙: AI에게 줄 작업 규칙을 문서로 고정.

### 3주차 (10/10) — PRD와 작은 변경 하나 (PR #8, `docs/`)
가설 PRD(Q1~Q6, 수락조건 AC-01~07) → 벤치마크(Trello · GitHub Projects) → 5칸 구조도 → 와이어프레임 → 작은 변경 하나(제목 입력칸 안내 문구, AC-07) → 리뷰 요청을 같은 PR에 이어서 반영 → 인계 메모(`handoff.md`).
- 배운 점: 고치기 전에 문서로 범위를 먼저 정하고, 변경은 하나만 한다.

### 3주차 — 충돌 실습 (PR #9 · #10 · #13 · #16)
`feat/title-a`(AX 보드 A)와 `feat/title-b`(AX 보드 B)가 같은 줄을 고치게 한 뒤, A를 먼저 merge하고 B에서 충돌을 웹에서 해결했다. 한 번은 merge 없이 Close를 눌렀다가 다시 열었다 — Close와 Merge는 다르다.
- 배운 점: 충돌은 AI가 임의로 풀지 않고, 양쪽 내용을 보고 사람이 고른다(D6).

### 4주차 (10/17) — 데이터 수집 (PR #11, `practice/`)
- A: Palmer Penguins 공개 CSV 수집 → 점검 → 선택 → 변형.
- B: 웹 표(하키 팀 기록). 작업 환경에서 사이트가 막혀 브라우저로 받아 옮겼고, 옮기다 깨진 페이지를 원문 해시로 찾아냈다.
- C: USGS 지진 Atom 피드 수집과 재처리(새 요청 없이 저장본으로 다시 만들기).
- 배운 점: 출처와 이용 조건을 먼저 적고, 원문과 결과를 해시 · 행 수로 대조하고, 데이터가 말해 주는 범위를 넘는 주장은 구분한다.

### 10/22 — 기록 정리 (PR #12 · #14)
`docs/log.md`(무엇을 했나)와 `docs/decisions.md`(왜 그렇게 했나)를 나눠 남겼다. 업로드 중 글자 하나가 바뀐 것을 blob 해시 대조로 찾아 고쳤다(D18).

### 5주차 (10/24) — my-intro: AI API 연동 (`feat/my-intro` 브랜치)
자기소개 한 줄을 면접용 · SNS용 · 발표용으로 다듬어 주는 Next.js 앱. 이 브랜치는 main과 이력이 이어지지 않는 **별도 프로젝트**이고 merge하지 않는다.
- 순서: 가짜(mock) 결과로 화면 먼저 확인 → 실제 OpenRouter(`openrouter/free`) 연결.
- 배운 점: API 키는 서버(`app/api/...`)에서만 읽고 `.env`는 커밋하지 않는다(`.env.sample`만). 무료 모델은 빈 답이나 형식이 틀린 답을 주기도 해서 서버에서 다시 묻고 JSON만 골라낸다.

### 팀 액션러닝 — 6조 "실리콘밸리 발사대" (저장소 밖)
기업 연계 과제로 "미처리 메일 리마인더 봇"을 기획했다(10/3 PRD v1 → 10/10 문서 갱신 → 10/17 UI 시안). 팀 공동 산출물이고 실제 메일 캡처가 섞여 있어 **원문은 이 저장소에 올리지 않고** 경험만 적는다.
- 흐름: 유사 서비스 벤치마킹 → PRD 6질문 → 기업 인터뷰 질문지 → 구조도 v1 → v2(팀 구조도 3종 통합) → 와이어프레임(위치 코드로 화면 합의) → 인계 메모.
- 배운 점: 핵심 기능을 3개로 묶어 범위를 지킨다. 규칙으로 될 일은 AI에게 맡기지 않는다. 위험(로그인 제한 등)과 대비책을 미리 적는다. 문서를 덮어쓰기 전에 백업한다.

## AX 아이디어 보드 실행 방법

```bash
git clone https://github.com/mungn0603-code/ax-board-practice.git
cd ax-board-practice
npm install
npm run dev -- --port 3099
```

필요한 것: Node.js 18 이상. 키(`.env`)는 필요 없다. 수업 서버에서는 3099 대신 배정 포트(30NN)를 쓰고, 브라우저에서 `http://localhost:3099`를 연다.
